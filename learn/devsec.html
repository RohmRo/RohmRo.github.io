امنیت پایه برای برنامه‌نویس‌ها

امنیتمتوسط۹ دقیقه

مدیریت کلیدهای API، فایل env، ورودی کاربر و وابستگی‌ها.

چند اشتباه ساده، بیشتر حادثه‌های امنیتی پروژه‌های کوچک را می‌سازد. این فهرست را همیشه کنار دستت داشته باش.

۱. اسرار را در کد نگذار

کلیدهای API، رمز پایگاه داده و توکن‌ها را در فایل .env نگه دار و آن فایل را از Git حذف کن:

# .gitignore
.env
node_modules/
.venv/
*.pem
# .env
API_KEY=your-secret-key-here

۲. اگر کلیدی لو رفت

حذف آن از کامیت بعدی کافی نیست، چون در تاریخچه Git می‌ماند. فوراً کلید را در سرویس مربوط باطل (Revoke) کن و یک کلید جدید بساز.

۳. کد سمت کاربر عمومی است

احتیاطهر چیزی که در HTML یا جاوااسکریپت سایت بگذاری را همه می‌توانند ببینند. هرگز کلید API خصوصی (مثل کلید یک مدل زبانی) را در کد صفحه نگذار. برای اتصال امن، یک بک‌اند کوچک (مثلاً Cloudflare Workers یا یک سرور Node) بساز که کلید را نزد خودش نگه دارد و درخواست‌های سایتت را به آن سرویس برساند.

۴. ورودی کاربر را باور نکن

  • XSS: متن کاربر را مستقیم با innerHTML وارد صفحه نکن؛ از textContent استفاده کن.
  • SQL Injection: کوئری‌ها را هرگز با به‌هم‌چسباندن رشته نساز؛ از کوئری‌های پارامتری استفاده کن.
  • اعتبارسنجی را همیشه در سمت سرور هم انجام بده، نه فقط در مرورگر.
// Bad
el.innerHTML = userInput;

// Good
el.textContent = userInput;

۵. وابستگی‌ها و HTTPS

  • به‌طور منظم وابستگی‌ها را بررسی کن: npm audit برای Node و pip-audit برای Python.
  • سایت را همیشه با HTTPS ارائه بده؛ GitHub Pages این را رایگان فعال می‌کند.
  • از هر کتابخانه‌ای فقط وقتی لازم است استفاده کن؛ هر وابستگی یک سطح ریسک اضافه است.

۶. کمترین دسترسی

به هر کلید و حساب فقط دسترسی لازم را بده. اگر فقط خواندن کافی است، دسترسی نوشتن نده.
