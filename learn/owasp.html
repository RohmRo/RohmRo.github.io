ریسک‌های اصلی امنیت وب (OWASP Top 10)

امنیتمتوسط۹ دقیقه

مهم‌ترین دسته‌های آسیب‌پذیری وب و چطور از آن‌ها در کد جلوگیری کنیم.

OWASP فهرست دوره‌ای از رایج‌ترین ریسک‌های امنیتی برنامه‌های وب منتشر می‌کند. ترتیب و نام‌ها در نسخه‌های مختلف کمی فرق می‌کند؛ نسخه فعلی را از owasp.org ببین. دسته‌های ثابتش این‌هاست:

  • کنترل دسترسی ناقص: کاربر عادی به صفحه یا داده کاربر دیگر دسترسی پیدا می‌کند. راه‌حل: همیشه دسترسی را در سرور و برای هر درخواست بررسی کن.
  • پیکربندی ناامن: رمزهای پیش‌فرض، پنل‌های باز، پیام خطای کامل برای کاربر. راه‌حل: پیکربندی امن و بدون ویژگی اضافه.
  • وابستگی‌های قدیمی یا آلوده: کتابخانه‌های آسیب‌پذیر. راه‌حل: به‌روزرسانی منظم و ابزارهایی مثل npm audit.
  • خطاهای رمزنگاری: ارسال بدون HTTPS، هش ضعیف رمز. راه‌حل: HTTPS و الگوریتم‌هایی مثل bcrypt یا Argon2.
  • تزریق (Injection): SQL، دستور سیستم یا XSS. راه‌حل: کوئری پارامتری و escape خروجی.
  • طراحی ناامن: ضعف در خود منطق (مثلاً بدون محدودیت تعداد تلاش). راه‌حل: مدل‌سازی تهدید از ابتدا.
  • ضعف احراز هویت: رمز ضعیف، نشست بی‌انقضا. راه‌حل: 2FA، محدودیت تلاش، انقضای نشست.
  • نقص یکپارچگی داده و نرم‌افزار: اجرای کد یا بروزرسانی بدون بررسی امضا.
  • نبود لاگ و هشدار: حمله‌ای رخ می‌دهد و کسی نمی‌فهمد.

یک مثال: SQL Injection

// Bad: user input glued into the query
db.query("SELECT * FROM users WHERE name = '" + name + "'");

// Good: parameterized query
db.query("SELECT * FROM users WHERE name = ?", [name]);
نکتهبرای تمرین قانونی، سایت‌های آموزشی عمداً آسیب‌پذیر (مثل OWASP Juice Shop) را روی سیستم خودت اجرا کن.
